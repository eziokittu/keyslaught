# KeySlaught endless-mode gameplay contract

This document translates `gameidea.txt` and the confirmed setup decisions into an implementation boundary. It is intentionally mechanics-first; art, lore levels, the tutorial, and menu polish follow after the endless loop is playable.

## Presentation and target platform

- Primary release: desktop WebGL with a physical keyboard.
- Local verification: Windows 64-bit player.
- Reference viewport: 900 x 1000, giving the playfield a near-square footprint with extra vertical space for the top HUD and input/refresh presentation.
- The world uses 2D tilemaps and transform-driven movement. Gameplay must not depend on collision physics or simulated bullet trajectories.

## Endless run loop

1. Enemy words spawn in increasingly difficult waves and follow authored paths toward the library.
2. The player moves around the map to bring enemies and buildable ground cells into interaction range.
3. Typing a letter immediately attacks one valid in-range enemy.
4. Destroyed enemies drop brain cells, which are collected as the run currency.
5. Brain cells buy or upgrade turrets and activate/upgrade library abilities during the run.
6. Words reaching the library deal damage equal to their remaining letter count.
7. The run ends when library health reaches zero; later balancing can add victory milestones without changing this loop.

## Typed attacks and letter magazine

- Enemy words are normalized to uppercase for combat.
- Damage is sequential: `HELLO` becomes `ELLO`, then `LLO`, then `LO`, then `O`, then defeated.
- On each keypress, build the valid target set from enemies that:
  - are in the player's current range; and
  - require the typed letter as their next visible letter.
- From that set, attack the enemy closest to the library. Only an exact progress tie may be resolved randomly.
- Every valid A-Z key loads that letter into a bounded magazine. A loaded letter remains available until a matching in-range target can consume it.
- Loaded letters automatically fire when a matching enemy enters range. The target remains the matching enemy closest to the library, even if a different enemy entered range earlier.
- Only the enemy's current first letter is shootable. The enemy card shows that letter, while the top HUD shows the full remaining word.
- When the magazine is full, the player must trigger Reload before more letters can be accepted.
- Reload clears the magazine after a duration derived from its occupied slots (initial design approximation: 0.5 seconds per occupied slot). Upgrades and gun definitions may modify this rate.
- Whether Reload can be triggered before the magazine is full remains configurable.

## Targeting and damage

- There are no physical projectile trajectories. Visual shots are presentation events after deterministic target selection.
- The player's attack range, attack cadence, reload duration, and magazine capacity are upgradeable.
- The player has no health. Enemy contact corrupts the player's gun for a configured duration, disabling typed attacks.
- Library damage equals the number of letters remaining when an enemy arrives.

## Turret families

Initial turret definitions are data, not hard-coded branches:

| Family | Letter coverage | Intended profile |
| --- | --- | --- |
| Teacher | A-F, G-M, N-T, or U-Z | High range and fire rate, narrow coverage |
| Engineer | A-M or N-Z | Medium range and fire rate |
| Scientist | A-Z | Low range and fire rate, universal coverage |
| President | A, E, I, O, U, S, T | Medium range and fire rate |

Turrets select the closest-to-library valid target after every shot. They do not consume the player's magazine.

## Library abilities

- **History:** enemies move backward along their paths for an initial five seconds.
- **Social Media Influence:** enemies freeze for an initial five seconds.
- **Politics:** the front three enemies lose the first half of their remaining letters, rounded up. `MILK` becomes `LK`; `HELLO` becomes `LO`.

Ability definitions should expose duration, target count, magnitude, cooldown, and upgrade curve as data.

## Architecture boundary

- Immutable base data: `EnemyDefinition`, `TurretDefinition`, `GunDefinition`, `AbilityDefinition`, `WaveDefinition`, and upgrade definitions as ScriptableObjects.
- Runtime state: word progress, path progress, cooldowns, corruption, magazine contents, wave state, library health, run currency, and temporary upgrades.
- Persistent state: permanent research upgrades, first-launch/tutorial status, lore completion, and endless-mode unlock.
- Scene-authored core: a serialized `GameManager` coordinating independently testable services/components. Player, enemies, orthogonal paths, library, buildable/blocked ground, and UI stay editable as scenes, Tilemaps, Tile Palettes, and prefabs rather than being generated by an opaque runtime bootstrap.
- Presentation listens to events from mechanics and may be replaced without changing rules.

## Planned mechanics order

1. Pure word, targeting, magazine, and library-damage rules with EditMode tests.
2. Authored square/portrait arena, player movement, enemy path traversal, and spawning.
3. Typed player attacks, corruption, refresh, and direct-shot presentation events.
4. Library health, brain-cell drops/collection, run state, and wave escalation.
5. Turret placement, four turret families, targeting, and upgrades.
6. History, Social Media Influence, Politics, and library repair.
7. Permanent research persistence and the endless-mode day-one progression hook.
8. PlayMode regression coverage, WebGL build, Windows build, and browser deployment.
